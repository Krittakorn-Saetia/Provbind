**`controller/watch.py`**

- **Fails closed.** Any verification failure, including cosign missing, gives `verified: false`. It used to return `True`.
- **Verification uses Role 2's `compiler.evidence`,** which also requires an image signature for the digest. cosign v3's `verify` alone passes an attested but unsigned image.

- **Removes bindings of deleted pods,** and a restarted container's old IDs (Role 3's Q5).
- **No silent mock mode.** Without the Kubernetes client or a cluster it exits 3 instead of writing a fake binding.
- **`--image REF@DIGEST`** binds one image without a cluster, for local checks and tests. `--once` binds the pods that exist and exits.

**`alerts/run.py`**

- **Once per detection.** Detections already in the log are skipped. Rerunning `--once` used to alert everything again, with the same IDs.
- **Complete lines only.** A half-written detection line waits for its newline instead of being dropped.
- **Attribution looks up the file the clause names.** For D_write that's `/etc/passwd`, not the writer `/tmp/.x9`.
- **Signing identity comes from the envelope,** or `null`. It used to invent `sf9-26/local-build` and Rekor index `123456789`.
- **κ comes from the binding.** ρ comes from `context.declared`, package and depth.
- **Chains** are keyed by container. The chain's pids are the detections' own pids, not their parent's, so the app's other children don't join an attack chain. Times are the events' own `time`s, 60 s window. Chain IDs come from the first detection, so they are stable across restarts.
- **`violated_clause`** reads `kind: path: detail`.

**`alerts/trust.py`: new, the Phase 6 trust loop**

- **Alerts once, on the 1 → 0 flip,** and saves state in `trust/<hex>.json`.
- **Reacts within 2 s of an input changing,** so trust-1's 30 s window works; otherwise it runs every ΔR = 300 s.
- **Helpers:** `python -m alerts.trust key-id` prints a key id, and `set-key --state revoked` marks a key revoked (scenario trust-2).

**Results on Korn-PC's stand-in:** all pass.

**PH5-04 is judged on S, the score Eq. (65) defines.** The whole-number score shown in alerts is only its display, and rounding can tie two alerts that S tells apart:

- An undeclared file and a declared one of depth 39 or more both show 90. For a root pod, 100·S = 70 + 20·d/(1+d), which rounds up to 90 from depth 39, while S itself always stays lower.
- So every score's `score_parts` carries S, and ranking uses it: `alerts.show --rank` orders by score, then by S.
- The test checks 7,200 cases (6 types, 2 origins, 3 pods, depths 0–199). In every case S is lower for the declared file, its rounded score is never higher, and the ranking puts the undeclared file first. The result's note names the display tie.
- Korn is proposing one line for the Test Plan's update log (§10): the paper should say that ranking uses S.

## Decisions made for you (change them if you disagree)

| Item | Choice |
|---|---|
| Trust alert shape | Written to `alerts.jsonl` and the log like any alert. `class: "trust"`, `subclass` = the failed checks joined by `+`, `trust_reason` = their list, `runtime_state` = `conforming` or `deviating`, plus `findings` and `latency_s`. Role 1's E2E-11 recognises it. |
| Trust alert score | 70 (High). The plan gives trust alerts no score; this is a proposal. |
| New run-folder files (Role 4's only) | `contexts/<hex>.json`, `contexts/<hex>.sbom.json` (the SBOM's edges), `trust/<hex>.json`, `keystatus.json`, `builder_denylist.json`, `advisories/*.json` (Role 1's `trust.sh` writes there), `log/checkpoints.jsonl` (only with a log key), `logs/` (make demo) |
| Dependency path | A list of purls from a root package (depth 1; the application root at depth 0 is implicit) to the owning package, so its length is the depth. `null` without stored edges. |
| Admission checks | `checks` = `v_sig`, `v_B`, `v_P`, `v_trans` (null when offline or no bundle), `v_trust` (null when no key id). v_trust is re-read on every admission. |
| `keystatus.json` | `{"keys": {"<key id>": {"state": "active\|rotated\|disabled\|revoked", "since": TIME}}}`. The key id is `sha256:` + SHA-256 of the public key's DER bytes. |
| Key rotated after the image was verified | Trust kept (Explanation §9 policy) |
| No transparency record (offline signing) | The trans check is "not applicable" and doesn't withdraw trust |
| s_origin for CONFIGURED (D_net) | 0.5, as for anything not AUTHENTICATED (the plan names only AUTHENTICATED and INFERRED) |
| Alert additions (readers ignore unknown fields) | `namespace`, `pod`, `container_id`, `pid`, `ppid`, `score_parts`, `attribution.dependency_path` |
| Binding additions | `ref`, `reason` |
